- **Diagnosed and fixed production 500s on `/api/browse` and `/api/audio`** (band-magic live music streaming was down):
  - Root cause #1: cross-project IAM gap. `gs://rollingblackoutband` (the real track storage) lives in project `rollingblackoutstorage`, but the Cloud Run runtime SA `band-magic-runner@rollingblackoutapp.iam.gserviceaccount.com` only had roles granted in `rollingblackoutapp` (via `google_project_iam_member.runner_roles`, project-scoped). Cross-project grants need their own mechanism.
  - Root cause #2: `@google-cloud/storage@7.21.0` pulled an outdated `google-auth-library@9.15.1` → `gcp-metadata@6.1.1`, which threw `"Invalid response from metadata service: incorrect Metadata-Flavor header"` against the Cloud Run metadata server. Rest of the app (Firestore/Secret Manager/googleapis) already used `gcp-metadata@8.1.x` via newer `google-auth-library@10.x` — same class of problem as the existing `gaxios` override.
  - Edge-runtime and header-spoofing theories (raised earlier) were both ruled out: no route sets `runtime = 'edge'`; Cloud Run invoker for `band-magic` is locked to the IAP service agent only, so `x-goog-authenticated-user-email` is trustworthy.
